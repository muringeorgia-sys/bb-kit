# Внешние системы и прод

Адреса, доступы и ограничения вашего продукта - в `product-context.md`. Здесь - общие правила.

## Внешние системы

Вики, трекер задач, BI, системы аналитики и макеты открывай тем способом, который указан в `product-context.md`, раздел «Доступы». Типовые варианты:

- коннектор MCP (облачный или локальный) - если он есть в сессии;
- браузер пользователя через расширение Claude in Chrome (инструменты `mcp__claude-in-chrome__*`) или управляемый браузер bb-browser: данные бери через `fetch` к REST API из вкладки нужного домена (сессия уже есть), а не кликами;
- API с токеном из переменной окружения. Токен не печатай и не пиши в файлы.

Нужный способ недоступен (браузер не подключён, коннектор не авторизован) - остановись, попроси пользователя подключить и продолжай после его ответа. Запасные пути, которых нет в `product-context.md`, не придумывай.

Ограничения браузерных инструментов: таймаут вызова JS около 45 с - не больше 3-4 запросов на запись за вызов; длинный вывод режется - большой результат выводи на страницу и читай текстом. После таймаута сначала проверь состояние на сервере, потом повторяй - иначе дубли.

## Прод и тестовый стенд

Текущее поведение и актуальные данные смотри на проде (адрес - `product-context.md`): экраны, тексты, цены, сетевые запросы. Только чтение: ничего не отправляй, не публикуй, не оплачивай и не меняй.

Тестовый стенд - только для сценариев, перечисленных в `product-context.md`. Шаги до отправки снимай на проде.

Сценарии с записью (создать, оплатить, удалить) смотри на проде до шага отправки и дальше не иди. То, что осталось непроверенным, - в список «Допущения», в PRD без пометок.

Зачем: снять текущий user flow по шагам, точные тексты экранов и ошибок, граничные случаи (пустое состояние, отказ, повтор) и сетевые запросы (какие эндпоинты и поля уже есть). Всё найденное идёт в «Контекст», «Как должно быть» и критерии приёмки.

Границы для всех сред: реквизиты банковских карт, пароли и коды из SMS в поля не вводишь сам - если сценарий упёрся в них, попроси пользователя пройти этот шаг и продолжай после.
