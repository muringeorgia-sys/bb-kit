# Релизы — плагин bb

Панель релизов по вашей Jira Cloud: итог прошлого релиза, прогноз текущего, готовность следующего и кейсы «вне нормы» (хвосты, неготовность, изменения скоупа, застрявшие задачи). Вы ставите свой итог и причину, скрываете кейсы, меняете статус и релиз в Jira по кнопке. Telegram-бот присылает сводку и ведёт проджект-менеджеров и продактов по проблемам.

## Что делает

| Раздел | Что видно |
|---|---|
| Обзор | Три релиза карточками, «Сначала это» — самые серьёзные кейсы, группы «Вне нормы», бот и рассылка |
| Релиз | Переключатель релизов, полоса исходов = фильтр, эпики по исходам, задачи вне эпиков, «Сняли до старта». Карточка эпика: ваш итог, причина, действия в Jira, задачи, история |
| Вне нормы | 18 видов кейсов в 4 группах, «По видам» или «По эпикам», фильтры. Карточка кейса: скрыть с причиной, действия в Jira |
| Бот | Вопросы продактам, что видят ПМ, журнал «Решено» |
| Настройки | Доступы к боту (логины ПМ и продактов, продукты), известные проблемы (метки и сроки), Telegram, как считаем |

| Кнопка / расписание | Что делает |
|---|---|
| Обновить | Сбор из Jira по всем продуктам (около минуты на продукт) |
| Будни 10:00 | Обновить + сводки в Telegram; если bb был закрыт — догоняет при запуске (10:00–18:00, раз в день). Время — по часам компьютера |
| Jira: статус, релиз | Переход статуса и перенос релиза (эпик и его незакрытые задачи) с подтверждением |

Бот в Telegram: ПМ получают «Полный отчёт» и «Решать по шагам» по задачам разработки и их эпикам, отмечают «Исправил в Jira» или «Написал в Jira»; после следующего обновления бот проверяет, ушла ли проблема. Продакты получают «Ждут моего решения», «Мои эпики», «Готовность релиза». Бот в Jira ничего не пишет.

## Как плагин читает вашу Jira

- Релиз = версия Jira с именем `<продукт> ДД/ММ/ГГГГ`, например `Продукт A 25/12/2026`. Версия с той же датой должна быть в каждом проекте (эпики, разработка, дизайн, QA).
- Эпики — в проекте эпиков, задачи разработки — дочерние задачи эпика в проекте разработки. Проекты дизайна и QA-анализа — необязательны.
- Несколько продуктов в одних проектах: продукт задаёт начало имени версии и значение поля эпика «Продукт».
- Прошлый релиз — последняя версия до сегодня, текущий — ближайшая, следующий — за ней. Старт спринта — день после прошлого релиза; поправить можно в панели.
- Стадии эпика и группы задач считаются по названиям статусов. Встроенные названия — ниже; другие — в настройке «Статусы Jira».

## Что нужно

| Что | Зачем |
|---|---|
| bb ≥ 0.46 | Сам плагин |
| Jira Cloud, email и [API-токен](https://id.atlassian.com/manage-profile/security/api-tokens) | Чтение эпиков, задач, версий и истории; смена статуса и релиза по кнопке |
| Telegram-бот от [@BotFather](https://t.me/BotFather) (необязательно) | Сводки и режим ПМ и продактов |
| Claude Code CLI с входом в аккаунт (необязательно) | Проверка комментариев ПМ моделью Haiku; без CLI работает запасное правило |

## Установка

```bash
bb marketplace add git:github.com/muringeorgia-sys/bb-kit@main --subdirectory bb
bb plugin install releases@bb-kit
```

Затем bb → Settings → Installed plugins → «Релизы». Пока обязательные настройки пусты, панель показывает, чего не хватает.

## Настройки

| Настройка | Что вписать |
|---|---|
| Адрес вашей Jira | `https://your-company.atlassian.net` |
| Email пользователя Jira | Под ним плагин читает Jira и меняет статус и релиз по вашей кнопке |
| API-токен Jira | Секрет bb, в панель не уходит |
| Проект эпиков, проект задач разработки | Ключи проектов, например `PROJ` и `DEV` |
| Проект дизайна, проект QA-анализа | Необязательно |
| Продукты | JSON, пример ниже |
| Поля «Продукт», «Ссылка на требования», «Ссылка на дизайн», «Не нужен дизайн» | id полей вида `customfield_12345`, все необязательны. Без поля «Ссылка на требования» правило «нет ссылки на требования» выключено |
| Статусы Jira | JSON, необязательно, пример ниже |
| Токен Telegram-бота | Секрет bb. Без токена панель работает, бот и сводки выключены |
| Чат сводки | id чата, необязательно. Пусто — напишите боту `/start` и нажмите в панели «Найти чат» |
| Часовой пояс | Часы от UTC, например `3`. Пусто — пояс компьютера |
| Путь к Claude CLI | Пусто — `~/.local/bin/claude` или `claude` из PATH |

Продукты:

```json
[
  { "id": "a", "name": "Продукт A", "emoji": "🚀" },
  { "id": "b", "name": "Продукт B", "short": "B", "version": "Prod B", "field": "Продукт B" }
]
```

`id` — латиница в нижнем регистре; `name` — имя в панели, начало имени версии и значение поля «Продукт». `version` и `field` нужны, только если они отличаются от `name`. Первый продукт — основной.

Из терминала: `bb plugin config releases set projectEpic PROJ`.

Статусы — можно заменить любую часть встроенного набора:

| Ключ | Встроено | Смысл |
|---|---|---|
| `groups.done` | Done, Ready to release, Готово | Задача готова |
| `groups.test` | Review, Ready to test, Testing, Проверка, Тестирование, In Testing | В тесте |
| `groups.hold` / `groups.kick` | On Hold, Holding / Kickback | Пауза / возврат на доработку |
| `groups.todo` | Backlog, To Do, К выполнению, Open, Selected for Development, Сделать | Не начата. Остальные статусы — «в работе» |
| `phases.pre` | Backlog, Инициатива, Исследование, Оценка и приоритизация, Формирование требований, … | Эпик: требования |
| `phases.qa` | Бэклог QA анализа, В работе QA, QA анализ, … | Эпик: QA-анализ |
| `phases.design` | Бэклог дизайна, Дизайн, На согласовании, На оценку, Готово к дизайну | Эпик: дизайн |
| `phases.ready` / `phases.dev` | Готово к тех оценке, Тех оценка, … / Бэклог разработки, Разработка | Эпик готов к разработке / в разработке |
| `phases.done` / `phases.parked` | Готово к выпуску, Выпущено / Отложено, Отклонено, Отменено | Эпик готов / снят |
| `designDone`, `qaDone` | Дизайн готов, QA анализ завершён | Конечные статусы задач дизайна и QA |
| `epicReady`, `epicReleased`, `canceled`, `rejected` | Готово к выпуску, Выпущено, Отменено, Отклонено | Особые статусы эпика |

Пример: `{"phases":{"done":["Ready for release","Released"]},"epicReady":"Ready for release","epicReleased":"Released"}`.

## Безопасность

- Токены Jira и Telegram — только в секретах bb (файл с правами 0600), в панель и в репозиторий не попадают.
- Запись в Jira — только переход статуса и смена Fix Version, только по вашей кнопке с подтверждением.
- Бот отвечает только логинам из списка «Доступы» и только пока запущен bb.
- Тексты комментариев ПМ уходят в Claude CLI, если он есть.
- Удалить: `bb plugin remove releases` (удалит настройки и секреты). Папка данных остаётся.

## Данные

Папка `~/.config/bb-releases/`:

| Файл | Что |
|---|---|
| `data.json`, `data-<id>.json` | Снимок Jira по продуктам |
| `notes.json` | Ваши итоги, причины, скрытые кейсы, даты спринтов, доступы, чат сводки |
| `history/` | Ежедневные срезы кейсов (метка «новый») |
| `journal.jsonl`, `pm-log.jsonl` | Журнал записи в Jira, отправок и действий в боте |
| `pm-state.json`, `pm-claims.json`, `pm-asks.json` | Сессии бота, отметки «Решено», вопросы продактам |
| `rev.json`, `rev-<id>.json` | Необязательно: ожидаемая выручка эпиков `{"КЛЮЧ-ЭПИКА": число}` из другого инструмента |
| `config.json` | Необязательно, только для `core/run.mjs`: проекты, поля, продукты без секретов |

## Файлы плагина

| Файл | Что |
|---|---|
| `server.ts` | Настройки, RPC панели, бот (long polling), расписание |
| `app.tsx`, `release.tsx`, `issues.tsx`, `settings.tsx`, `ui.tsx` | Панель |
| `core/core.mjs` | Логика: сбор из Jira, итоги, прогноз, кейсы, известные проблемы, Telegram, запись в Jira |
| `core/pm.mjs` | Бот: режимы ПМ и продакта, обучение, утренняя рассылка |
| `core/run.mjs` | Без bb: `node core/run.mjs check \| refresh \| view [--list] \| telegram --dry \| morning --dry \| pm-list \| po-list`. Доступы — переменные `JIRA_URL`, `JIRA_EMAIL`, `JIRA_API_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` |
| `core/test_core.mjs` | Офлайн-тест на вымышленной Jira: `node core/test_core.mjs` → «ошибок 0» |
